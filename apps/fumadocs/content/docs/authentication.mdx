## Sovereign mode authentication

When running locally or via the native Tauri 2.0 shell, Selvam operates in **Sovereign Mode**:

```bash
SOVEREIGN_MODE=true pnpm dev:web
# or for native desktop
pnpm desktop:dev
```

In sovereign mode:

1. **Instant Session Provisioning**: Route handlers and Server Components automatically receive an active sovereign session bound to the local identity (`sovereign-user`, name: `Aranga`).
2. **Zero Login Friction**: The desktop and web application boot directly into the dashboard without prompting for credentials or contacting any external authentication server.
3. **Owner-Scoped Relational Security**: All database queries and mutations continue to enforce strict `user_id` ownership constraints in PostgreSQL, ensuring complete relational data isolation.

## Sovereign Hardware Vault (`packages/auth/src/vault.ts`)

For encrypting sensitive credentials, API keys, and local documents, Selvam implements an authenticated hardware-grade vault:

### Binary specification

The encrypted payload uses a custom authenticated binary format:

```text
+-----------------------+---------+---------------+---------------+---------------+------------------+
| Magic Header ("SELV") | Version | Salt          | IV            | Auth Tag      | Encrypted Data   |
| 4 bytes (0x53454c56)  | 1 byte  | 16 bytes      | 12 bytes      | 16 bytes      | Variable length  |
+-----------------------+---------+---------------+---------------+---------------+------------------+
```

- **Cipher**: `AES-256-GCM` (Galois/Counter Mode) providing both confidentiality and cryptographic integrity.
- **Key Derivation**: `PBKDF2` using `HMAC-SHA-512` with 100,000 iterations and a 16-byte cryptographically secure random salt (`node:crypto.randomBytes`).
- **Initialization Vector (IV)**: 12-byte random IV per encryption operation to prevent replay and pattern attacks.
- **Integrity Tag**: 16-byte GCM authentication tag verified in constant time (`timingSafeEqual`) prior to decryption.

### Usage in code

```typescript
import { SovereignVault } from "@portfolio/auth";

// Derive key from master secret or hardware passphrase
const vault = new SovereignVault(process.env.BETTER_AUTH_SECRET);

// Encrypt payload
const encryptedBuffer = await vault.encrypt(Buffer.from("sensitive financial data"));

// Decrypt with integrity check
const decryptedBuffer = await vault.decrypt(encryptedBuffer);
```

## Local Document Vault

Uploaded statement files, tradebooks, and payslips are retained directly on the local filesystem under:

```text
./data/vault/documents/
```

- **Cryptographic Fingerprinting**: Every imported document is hashed using SHA-256. Repeat uploads of the same file are detected and deduplicated instantly without re-processing.
- **Zero Cloud Reliance**: Replaces external cloud storage dependencies (such as Google Drive or Amazon S3) with fast, private on-device storage.
- **Air-Gapped Access**: Document retrievals and downloads stream directly from local disk through authenticated Next.js route handlers with content sniffing disabled.

## Optional authentication providers

While sovereign mode is the default and recommended operating pattern, Selvam also supports traditional authentication for multi-user shared server environments:

- **Email and Password**: Local email/password authentication with a 12-character minimum password requirement and database-backed rate limiting.
- **Google OAuth (Optional)**: Can be enabled by supplying `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`. When unconfigured, Google OAuth buttons are automatically hidden from the interface.

## Persistent session management

Database sessions are stored directly in PostgreSQL (or embedded PGlite) with a rolling one-year lifetime. In production, sessions are persisted via secure HTTP-only cookies with `SameSite=Lax` protection.
