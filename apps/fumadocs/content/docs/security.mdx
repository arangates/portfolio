## Core security principles

### 1. Sovereign data isolation

Every portfolio, salary, tradebook, household, and FIRE record carries a strictly enforced `user_id` foreign key. In sovereign mode, requests are automatically bound to the verified local sovereign identity (`sovereign-user`). Clients never supply, modify, or choose the financial record owner.

### 2. Zero third-party telemetry

Selvam contains zero third-party telemetry scripts, zero tracking pixels, and zero remote logging services. Your financial balances, holdings, transaction histories, and net worth remain strictly on your physical hardware.

### 3. AES-256-GCM Hardware Vault (`packages/auth/src/vault.ts`)

For encrypted storage of credentials and local document payloads, Selvam implements standard Galois/Counter Mode (`AES-256-GCM`) authenticated encryption:

- **Key Derivation**: 100,000 iterations of `PBKDF2-HMAC-SHA-512` over a 16-byte cryptographically secure random salt.
- **Unique IVs**: Every encryption call generates a fresh 12-byte initialization vector (`node:crypto.randomBytes`).
- **Integrity Verification**: Prior to decrypting any payload, the 16-byte GCM authentication tag is validated using constant-time comparison (`timingSafeEqual`) to prevent padding-oracle and timing-channel attacks.

### 4. Local Document Vault (`./data/vault/documents/`)

Original broker statements, tradebook files, and payslips are archived locally rather than uploaded to third-party cloud buckets:

- **SHA-256 Deduplication**: Every file is fingerprinted upon upload. Repeated uploads of the exact same document are detected immediately and skipped to preserve ledger integrity.
- **In-Memory Parsing**: Sensitive documents (such as salary slips) are parsed in memory by `@portfolio/parsers`. The database stores normalized financial ledger entries and cryptographic fingerprints, discarding unneeded personal identifiers (such as national tax IDs or personal home addresses).
- **Secure File Streaming**: Document downloads stream directly from local disk through authenticated route handlers with `X-Content-Type-Options: nosniff` and `Cache-Control: no-store` headers.

### 5. Architectural boundary isolation

Selvam's Clean Architecture prevents accidental data leakage across layers:

- **Pure Engines (`@portfolio/calc`, `@portfolio/parsers`)**: Have zero network or database dependencies. They cannot open sockets or perform unauthorized I/O.
- **Server-Only Modules**: Database query and mutation packages import `server-only`, guaranteeing that data-access routines are never bundled into client-side JavaScript.
- **Localhost Binding**: In standalone and Docker environments, administrative interfaces (such as Drizzle Studio) bind strictly to loopback (`127.0.0.1`), preventing exposure across local networks.

## Operational rules

1. **Keep Secrets Private**: Keep master encryption secrets (`BETTER_AUTH_SECRET`) in private, git-ignored `.env` files.
2. **Back Up Local Data**: Back up the `./data/` directory (containing `./data/selvam.db` and `./data/vault/documents/`) using encrypted local or external disk backups.
3. **Verify Hashes**: All document imports record SHA-256 digests in the database audit log for tamper verification.
