## Architecture & directory structure

All email components, templates, utilities, and sending services reside in the dedicated workspace package `packages/emails` (`@portfolio/emails`):

```text
packages/emails/
├── package.json             # @portfolio/emails package definition
├── tsconfig.json            # TypeScript configuration
├── README.md                # Package documentation
└── src/
    ├── components/          # Reusable layout and typography components
    │   ├── EmailButton.tsx  # Cross-client styled action buttons
    │   ├── EmailCard.tsx    # Responsive content card containers
    │   ├── EmailDivider.tsx # Visual horizontal dividers
    │   ├── EmailLayout.tsx  # Base container with branded header and footer
    │   └── EmailText.tsx    # Typography primitives (H1–H3, Body, Caption)
    ├── config.ts            # Brand colors, typography, and sender configuration
    ├── index.ts             # Public module exports
    ├── services/            # Email dispatch and Resend integration
    │   └── email-service.tsx# Typed sending functions and legacy fallback
    ├── templates/           # Production-ready email templates
    │   ├── ActivationEmail.tsx # User account activation and email verification
    │   ├── BillsEmail.tsx   # Bill payment reminders and urgency alerts
    │   ├── ContractsEmail.tsx # Contract expiration and renewal notices
    │   ├── DepositsEmail.tsx# Term deposit maturity notifications
    │   ├── InvestmentsEmail.tsx # Portfolio valuation and movement summaries
    │   ├── NotificationEmail.tsx # General multi-event financial digest
    │   ├── TestEmail.tsx    # Delivery test and setup verification
    │   └── WelcomeEmail.tsx # Onboarding feature walkthrough
    ├── theme.ts             # Barebones Tailwind styling configuration
    ├── theme-fonts.tsx      # Cross-client Inter font definitions
    └── utils/               # Server-side rendering helpers
        └── render-email.tsx # HTML and plaintext generation utilities
```

## Base design system

Emails adhere to Selvam's design language, ensuring brand consistency between the web dashboard and user inboxes.

### Layout wrapper (`EmailLayout`)

Every email is wrapped by `EmailLayout`:

- **Fixed max-width**: 600px centered container optimized for mobile and desktop webmail clients.
- **Header**: Branded Selvam mark and application title.
- **Footer**: Support contact links, security notice, and unsubscription or notification preference guidelines.
- **Dark mode**: Adaptive dark backgrounds on supported email clients (Apple Mail, Outlook on iOS/macOS).
- **Hidden preheader**: `previewText` attribute populated to provide meaningful inbox list snippets.

## Email services & dispatch

Email sending is centralized in `apps/web/src/emails/services/email-service.tsx`.

### Core dispatch functions

```typescript
// Generic typed sender with idempotency support
export async function sendTemplatedEmail(
  to: string,
  subject: string,
  template: React.ReactElement,
  idempotencyKey?: string,
): Promise<{ success: boolean; data?: unknown; error?: unknown }>;

// Domain-specific helper functions
export async function sendBillsEmail(to: string, bills: BillItem[], ...);
export async function sendContractsEmail(to: string, contracts: ContractItem[], ...);
export async function sendDepositsEmail(to: string, deposits: DepositItem[], ...);
export async function sendInvestmentsEmail(to: string, investments: InvestmentItem[], ...);
export async function sendNotificationEmail(to: string, events: EventItem[], ...);
export async function sendWelcomeEmail(to: string, userName: string, idempotencyKey?: string);
export async function sendTestTemplatedEmail(to: string, userName?: string, idempotencyKey?: string);

// Legacy plain-text fallback
export async function sendLegacyTextEmail(to: string, subject: string, textBody: string, idempotencyKey?: string);
```

### Idempotency and delivery guarantees

Financial alerts and reminders derive an idempotency key before dispatching:

```typescript
const idempotencyKey = `reminders-${userId}-${dateString}`;
await sendNotificationEmail(user.email, events, events.length, 7, "Daily Digest", idempotencyKey);
```

Passing the key to Resend ensures that automated retries, cron job replays, or background worker timeouts do not generate duplicate messages to the user.

### System integration

The notification subsystem (`apps/web/src/lib/push-notifications.ts`) delegates to React Email:

```typescript
// Test email trigger
export async function sendTestEmail(userId: string) {
  const user = await getUser(userId);
  return sendTestTemplatedEmail(user.email, user.name);
}

// Scheduled financial digests
export async function sendScheduledReminders(userId: string, events: FinancialEvent[]) {
  const user = await getUser(userId);
  const eventItems = events.map(toEventItem);
  return sendNotificationEmail(user.email, eventItems, eventItems.length, 7);
}
```

## Environment configuration

To deliver emails in development or production, configure the following environment variables:

```bash
# Resend API key for outbound transactional emails
RESEND_API_KEY=re_123456789...

# Verified sender address matching your verified DNS domain
EMAIL_FROM=Selvam <notifications@selvam.app>

# Application URL used for generating CTA action links
BETTER_AUTH_URL=https://myselvam.vercel.app
```

## Best practices & email client compatibility

When creating new email templates, adhere to these guidelines:

1. **Table-based structure**: Rely on `@react-email/components` (`Section`, `Row`, `Column`) rather than CSS flexbox or CSS grid, which are unsupported by Outlook for Windows.
2. **Inline styles via Tailwind**: Use `@react-email/tailwind` with the shared config in `apps/web/src/emails/config.ts`. Avoid external stylesheets.
3. **Escaped HTML entities**: Always escape angle brackets in JSX copy (use `&gt;` instead of `>` and `&lt;` instead of `<`) to avoid HTML parser ambiguities in older webmail clients.
4. **Explicit image dimensions**: Specify absolute `width` and `height` attributes on any included images or logos to prevent layout shifts before assets load.
5. **Plaintext fallback**: Ensure templates provide clean plaintext fallbacks rendered via `renderEmailToText()` for users on text-only or assistive devices.
