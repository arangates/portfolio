## Embedded PGlite reset (Sovereign Mode)

When running in sovereign mode with embedded PGlite, application data is stored in the local directory:

```text
./data/selvam.db
```

### Quick reset

To completely reset your local sovereign database:

```bash
# 1. Stop the application server (Ctrl+C)

# 2. Remove the local database folder
rm -rf ./data/selvam.db

# 3. Restart the server
SOVEREIGN_MODE=true pnpm dev:web
```

On restart:

1. PGlite automatically initializes a new SQLite-backed PostgreSQL directory at `./data/selvam.db`.
2. All 70 Drizzle migrations run automatically in ~450ms.
3. The sovereign user (`sovereign-user`) is auto-provisioned with an empty, clean portfolio ready for fresh imports.

### Resetting the document vault

If you also wish to clear archived statement files:

```bash
rm -rf ./data/vault/documents/*
```

## Guarded CLI reset (`pnpm db:reset-data`)

The repository also includes a guarded data-reset script for safely truncating rows while keeping tables and indexes intact:

<Steps>
  <Step title="Run a dry run inspection">
    From the repository root, run:

    ```bash
    pnpm db:reset-data
    ```

    The dry run prints:
    - The target database connection and host.
    - The number of applied migrations.
    - Every table with non-zero rows.
    - The exact confirmation command needed to proceed.

  </Step>

  <Step title="Execute with confirmation">
    Pass the confirmation flags:

    ```bash
    pnpm db:reset-data -- \
      --execute \
      --confirm=RESET_ALL_APPLICATION_DATA
    ```

    The command safely truncates all application tables in a single transaction, leaving the schema and Drizzle migration history intact.

  </Step>
</Steps>

## Docker Compose reset

When running Selvam via Docker Compose, reset the persistent volume:

```bash
# Remove containers and the persistent database volume
docker compose down -v

# Start with a fresh database
docker compose up -d
```
